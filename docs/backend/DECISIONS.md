# Frontend decisions from the backend answers

Later phases follow these. "Answers §n" is section n of `HeatGuard_Answers_For_Frontend.pdf` (backend team, 12 November 2026). Decisions D1 to D8 are in `FRONTEND_BACKEND_GAPS.md`.

## Agreed

| Topic                               | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | Source           |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------- |
| Consent policy version              | Send `policyVersion: "2026-11-v1"` with every `PUT /me/consents`. Defined once as `CONSENT_POLICY_VERSION` in `src/api/constants.ts`. Agree a new version when the privacy text changes                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | Answers §11      |
| "I understand" on What to do        | Acknowledge the first item of `GET /me/risk` `recommendations` (highest level first, code `worker.engine_action`) with `POST /recommendations/{id}/interventions` and `{ "status": "acknowledged" }`. Workers can only acknowledge their own                                                                                                                                                                                                                                                                                                                                                                                                                                                            | Answers §2       |
| Worker reasons                      | `reasons` arrive as engine text in the worker's language, not codes. Show them as received, as chips. Supervisors never receive reasons                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | Answers §4       |
| Hazards                             | `{ type: "dust", severity: "moderate" \| "high" }` and `{ type: "thunderstorm", severity: "possible" }`, each with `from` and `to`. Map them to the existing hazard rows and pills (dust: Moderate or High pill; thunderstorm: Possible pill)                                                                                                                                                                                                                                                                                                                                                                                                                                                           | Answers §4       |
| Next break place                    | The backend sends time and duration only. Show the fixed text "shaded rest area"                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | Answers §8       |
| Health profile save without consent | A save without health consent returns 409. Show "Turn on health sharing in My data to save your answers." with a link to My data                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | Answers §7       |
| Clearing the age range              | Send `ageRange: null` in `PUT /workers/{workerId}/health-profile` to clear a saved age range. "Not answered" that was never saved is left out                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | Answers §7       |
| Delete health answers               | Deleting does not withdraw consent (withdraw with `healthPrecautions: false` on `PUT /me/consents`). Delete confirmation: "Delete your health answers? This cannot be undone. Your sharing choice stays on until you turn it off below."                                                                                                                                                                                                                                                                                                                                                                                                                                                                | Answers §7       |
| Access log roles                    | `actorRole: "occupational_health"` shows "Occupational health viewed your health profile". Every other role is mapped to plain words; an unknown role shows "Someone at your site viewed your data". Never show the raw role                                                                                                                                                                                                                                                                                                                                                                                                                                                                            | Answers §6       |
| Error messages                      | `message` is an array of strings for 400 validation errors and a single string otherwise. For an array, show the first item only                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | Answers §12      |
| Site sensors                        | `systemHealth.siteSensors` is `null` when no sensor has ever reported: show "No site sensors". Otherwise it is `{ lastAt, ok }`: show the last reading time and an OK or Check pill                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | Answers §10      |
| Workers needing reduced exposure    | `GET /sites/{id}/plan` returns `workersNeedingReducedExposure`, a count only (no names or reasons). The count card stays                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | Answers §5, D1   |
| Suggested plan text                 | "What the suggested plan changes" is written by the app, by comparing `current` and `suggested` tasks per crew. Example: "Crew B: heavy work moved out of 11:00 to 14:00 and into 16:00"                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | Answers §9       |
| Saving and sending a plan           | Save edits with `PUT /sites/{id}/plan`, then send with `POST /sites/{id}/plan/send` and `{ "use": "current" }`. Send notifies no one (it sets `status` and `sentAt` and reruns the risk assessments), so the message stays: "Plan applied for today. Let your crews know about the changes."                                                                                                                                                                                                                                                                                                                                                                                                            | Answers §9       |
| Needs attention: help               | First aid alert or symptom report. "I am on my way" calls `POST /help-requests/{id}/acknowledge`, then "Mark resolved" calls `POST /help-requests/{id}/resolve`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | Answers §3       |
| Needs attention: critical           | A worker at Critical. New card in the danger style: "Worker [code] is at Critical. Stop their activity now." Buttons: Acknowledge (`acknowledged`) and Activity stopped (`implemented`)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | Answers §3       |
| Needs attention: crew_risk          | A crew at High or above. Buttons: Acknowledge (`acknowledged`) and Change shift timing (a link to the shift plan)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | Answers §3       |
| Needs attention: worker_care        | A worker with precautions. Shows the `need` only (`reduced_exposure` or `earlier_breaks`), never the reason. Buttons: Acknowledge (`acknowledged`) and Reassign (`reassigned`, chosen option in `note`)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | Answers §3, D1   |
| Interventions                       | `critical`, `crew_risk` and `worker_care` use `POST /recommendations/{recommendationId}/interventions`. Statuses: `acknowledged`, `implemented`, `reassigned`, `dismissed`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | Answers §3       |
| Supervisor action wording           | `supervisor.suspend_activity`: Stop the affected activity now. `supervisor.extra_breaks_reduce_load`: Add extra breaks and reduce heavy work. `supervisor.increase_monitoring`: Check on the crew more often. `supervisor.reschedule_before_peak`: Move heavy work before the hottest hours. `supervisor.review_ppe_cooling`: Check cooling and rest options for crews in heavy protective equipment. `supervisor.worker_reduced_exposure`: Worker [code] needs reduced exposure today. `supervisor.worker_earlier_breaks`: Worker [code] needs earlier breaks today. `crew.rotate_and_cool`: Rotate [crew] between hot and shaded tasks and add cooling. Unknown codes show the backend's English text | Answers §4       |
| Vercel previews                     | CORS allows preview addresses ending in `-ahmads-projects-727aea25.vercel.app`, production and `localhost:5173`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | Answers §13      |
| Worker codes                        | Screens show `workerCode` (for example W-0388), never the `workerId` UUID                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | Spec, Answers §3 |
